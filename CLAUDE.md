# CLAUDE.md — «Вылупляй и Перепродавай! Лавка Аномалий»

Главный файл для сборщика. Подробности — в `docs/`, порядок чтения — `docs/00-index.md`.

## Что строим
2D idle-тайкун в браузере: игрок держит лавку странных милых существ. Покупает яйцо, из него вылупляется аномалий с редкостью, игрок кормит его тапами (растут уровень и цена) и продаёт коллекционеру из очереди с торгом; на монеты прокачивает инкубаторы, витрину, помощников, районы покупателей. Дальше — офлайн-доход, коллекция, аномалий дня, перерождение «лавка в новом городе». Площадки: Яндекс Игры, потом CrazyGames и YouTube Playables. 6+ (на YouTube 13+), ru и en с первой вехи, телефон первым (обе ориентации, без блокировки), ПК тоже.
Стек: TypeScript + Vite + PixiJS 8 (сцена) + HTML/CSS поверх (интерфейс), Vitest, Playwright. Платформа — `src/platform/`, профили `yandex`, `null`, `youtube`. Числа и тексты — только в данных.

## Как работать
1. Старт: `bash init.sh`; читаешь `CLAUDE.md`, `docs/00-index.md`, «Состояние» в `progress.md`, ответы в `QUESTIONS.md`; берёшь первую фичу текущей вехи с `passes: false`.
2. Одна веха = одна сессия; вехи по порядку `feature_list.json → milestones`; одна фича за раз, «снизу вверх»: данные → правила → логика → состояние → UI → эффекты.
3. После фичи: её тесты и `npm run verify:fast` зелёные → `passes: true` → запись в `progress.md` по шаблону → «Состояние» → коммит `M0-04: сохранения через платформу` → push. Без зелёного вывода этой сессии `passes` не трогаешь.
4. Итог вехи — `docs/05`, раздел 1: полный `verify`, скриншоты, плейтестер, `git push origin HEAD:main`, итог по шаблону, последняя строка «Ждёт решения продюсера», стоп.
5. Ощущение игры (отклик тапа, темп, щедрость торга) — в `content/*.json` и ползунках `?debug=1`; продюсер пришлёт JSON.
6. Плейтестер — субагент в итоге вехи, один прогон; оценки ниже 3 — в фичи следующей вехи или в `progress.md` с причиной.
7. Шапка модуля `src/`: `// What:`, `// Called by:`, `// Keep:`. Перед фичей читай шапки слоя, целиком — только меняемые модули.
8. Разведка перед фичей: найди, что уже есть, и минимальный путь; строка «Разведка: …» в записи.
9. Перед фичей — `git pull`; есть записи другой сессии — читай «Состояние», сделанное не переделывай.
10. Фильтр сложности: проще через то, что есть; жанр — тап, рост числа, сделка. Усложнение без нужды — в `QUESTIONS.md`, а не в код. В итоге вехи честно пишешь, что не нравится в игре.
11. Лимит сессии: 6 часов работы или 3 сжатия контекста → «Состояние», коммит, push, стоп строкой «Остановка по лимиту сессии: продолжить новой сессией».
12. Ориентир — топовые игры жанра («стандарт жанра», названий чужих игр в репозитории нет): базу механик, экранов и подач берём оттуда и улучшаем — ищем их дыры и боль игроков и делаем максимально классно, удобно, интересно. Изобретаем своё только там, где у лучших дыра (решение продюсера 13.10.2026).

13. База геймдизайна продюсера — скилл аккаунта gamedesign-knowledge (виден облачной сессии при старте). Перед проектированием вехи и фич про первую минуту, прогрессию, монетизацию, сочность и лайвопс читай нужную выжимку по его карте (core-loop, onboarding-ftue, progression, fomo-retention-monetization, juiciness, liveops-content, platforms-distribution). В записях ссылайся «по базе геймдизайна, раздел X». Файлы скилла в репозиторий не копировать: он публичный. Не видишь скилл — первой строкой итога «скилл базы не виден».

Работаешь автономно: неясно — разумный вариант и запись в `QUESTIONS.md`. Правки точечные. Заявление о прогрессе — только по выводу инструмента этой сессии.

## Экономия контекста и лимитов (обязательно)
- Одна веха = одна сессия; итог кончается строкой «Ждёт решения продюсера», новых вех сессия не открывает.
- Старт — только `CLAUDE.md`, `docs/00-index.md`, «Состояние» в `progress.md`; остальное по ссылкам и `grep`.
- По фиче — `verify:fast` (до 10 минут). Полный `verify` с e2e — один раз в итоге вехи, максимум один повтор, в фоне.
- Вывод команд — только хвостом `| tail -n 40`; логи и скриншоты — в `docs/evidence/<веха>/`, не в чат.
- Плейтестер — субагент в итоге вехи, один прогон.
- После каждой фичи — «Состояние» (до 10 строк: сделано, дальше, открытые вопросы).
- `progress.md` до 30 КБ; после вехи её записи — в `docs/archive/progress-<веха>.md`.
- «Лимит до / после» в итоге — по данным продюсера, иначе прочерк.

## Готово
Веха — `docs/05`, раздел 1. Игра к подаче: P1 — `passes: true`, P2 — `passes` или `deferred` с записью; `npm ci && npm run verify:full` в чистом клоне — код 0; в `docs/evidence/compliance/report.md` нет TODO; плейтестер ≥ 3,5 и ни одного пункта ниже 3 (или запасной порог); `check-release` и `check:youtube` зелёные; итог в `progress.md`.

## Жёсткие правила
1. Числа, тексты, цвета — в `content/` и `game.json`; кириллица в `src/**/*.ts` вне комментариев — тест красный.
2. Чужих брендов и персонажей нет нигде, включая код и коммиты: стоп-список `scripts/stopwords.json`. Нет рабочих названий, «онлайн», demo, beta для игрока.
3. Реклама — `docs/03`, раздел 2.
4. Внешние запросы: `yandex` — `/sdk.js` и Метрика, ссылки сообществ открывает игрок; `youtube` — только тег SDK `ytgame`, без Яндекса, аналитики, серверов, логинов, ссылок, обфускации; `null` — ни одного.
5. Бюджеты — `docs/02-tech.md`, раздел 8.
6. 6+: без смерти, крови, страха, жестокости; существа не страдают; яйца без ставок, в текстах нет «кейс», «лутбокс», «казино».
7. Ноль ошибок консоли и `alert`; мок и отладка в релиз не попадают.
8. `feature_list.json`: только `passes` и `deferred` (только P2, с записью). Критерий неверен — `QUESTIONS.md`, делаешь по критерию.
9. Репозиторий публичный: ни ключей, ни личных данных, ни путей с чужих компьютеров, ни названий чужих игр и разборов конкурентов. Исключение — стоп-списки. Обоснования чисел — «стандарт жанра».
10. `.github/workflows/` не меняешь (облако не может их пушить); нужна правка — пункт в `QUESTIONS.md`.

## Вопросы и общение с продюсером
- Работа не останавливается: вариант безопаснее для модерации и дешевле откатить, лучше данными; запись в `QUESTIONS.md` по шаблону (вопрос, варианты, выбор и почему, как переключить). Другой ответ продюсера — переделываешь.
- Правила общения приходят из облачного окружения (хук `SessionStart`); в репозиторий их не копируешь. Не видишь их — первой строкой «⚠️ правила общения из окружения не подхватились», дальше коротко, по-русски, итог первой строкой.
- Сессия работает в ветке `claude/…`; итог вехи — `git push origin HEAD:main` (ссылка продюсера собирается из `main`).
- Журнал, вопросы, отчёты — по-русски, коротко, сначала результат; код и имена — латиницей.
