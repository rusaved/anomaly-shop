# 05. Вехи и тесты

Рамка вокруг вех. Вехи и фичи с критериями — `feature_list.json` (критерии главнее пересказа). Доказательства — `docs/evidence/<веха>/`.

## 1. Веха
Одна веха = одна сессия. **Готово**, когда каждый пункт доказан выводом в этой сессии:
1. Все фичи вехи — `passes: true`; P2 — или `deferred: true` с записью в `progress.md` (что, почему, дата).
2. Полный `npm run verify` — код 0, лог `docs/evidence/<веха>/verify.txt`, последняя строка `EXIT=0`.
3. Скриншоты ключевых экранов (раздел 3) — ты их открыл и посмотрел.
4. Плейтестер — с M1, один прогон, `docs/evidence/<веха>/playtest.md`.
5. `git push origin HEAD:main`, ссылка продюсера обновилась.
6. Итог по шаблону `progress.md`, последняя строка «Ждёт решения продюсера»; записи вехи — в `docs/archive/progress-<веха>.md`; сессия стоит.

Резка: P1 не трогаешь, P2 — `deferred: true` с записью. Никогда не режем: телефон в обеих ориентациях, первую минуту, сделку с торгом, сохранения, паузу, ru и en, тесты модерации.

**Ссылка продюсера** — GitHub Pages: на push в `main` workflow собирает `build:pages` (playtest на моке, `?debug=1`, `?mock_lang=en`, метка «веха · дата · хеш») и публикует, без тестов. Проверка — `gh run list --workflow pages.yml --limit 1`, job `deploy` success; `gh` молчит — «публикация не проверена». JSON ползунков от продюсера переносишь в `content/*.json`.

## 2. Правила verify
| Что | Когда | Бюджет |
|---|---|---|
| `verify:fast` (typecheck, unit, validate:content) | после каждой фичи | ≤ 10 мин |
| `verify` (вся цепочка с e2e) | один раз в итоге вехи, максимум один повтор | ≤ 20 мин |
| `verify:full` (+ `@full`) | M7 и подача | ≤ 30 мин |
| `verify -- --no-e2e` | сборка посреди вехи, если нужно | ≤ 10 мин |

- e2e-ступени (`e2e`, `e2e:release`, `e2e:full`) — только в итоге вехи.
- Полный прогон — в фоне: `npm run verify -- --log docs/evidence/<веха>/verify.txt > /dev/null 2>&1; echo "EXIT=$?" >> docs/evidence/<веха>/verify.txt`; читаешь `tail -n 40`.
- Всегда зелёных заглушек нет. Ступень дольше бюджета — запись в `progress.md`, долгие тесты — под тег `@full`.

## 3. Тесты и скриншоты
- Состав тестов — `02`, раздел 10. e2e вехи: смоук (`ready()` один раз, ноль ошибок консоли), раскладка в трёх размерах, F5 после сделки, пауза и реклама на моке, языки; на M7 — матрица и сценарии `03`, раздел 6. Тест пункта `03` начинается с его ID.
- Скриншоты: `docs/evidence/<веха>/<экран>_<ширина>x<высота>_<язык>.png` в 375×812, 812×375, 1280×720; до 20 на веху, каждый ≤ 300 КБ (ширина до 1280). Полные — в `test-results/` или `raw/` (не в git).

## 4. Рубрика плейтестера
Субагент с чистым контекстом (`.claude/agents/playtester.md`) видит только игру и эту рубрику: телефон 60 с, боком 1 мин, ПК 4 мин.

| # | Критерий | 1 | 3 | 5 |
|---|---|---|---|---|
| 1 | За 5 секунд понятно, что нажать | не ясно | после подсказки | без слов |
| 2 | Отзывчивость тапа и интерфейса | задержка, промахи | вяло | мгновенно |
| 3 | Сочность: отклик на действие | нет отклика | не везде | каждое действие ощутимо |
| 4 | Цельность стиля | разнобой | безлико | единый узнаваемый мир |
| 5 | Первая минута по `01`, раздел 4 | обрывы, ожидание | темп проседает | новое каждые 10–20 с |
| 6 | Честность экономики и торга | обман | скупо | видно, за что платят больше |
| 7 | Хочется ещё | цели нет | цель далеко | следующее яйцо, улучшение, редкий видны |

Отчёт: баллы, средний, 3 худших момента с кадром, 3 правки. Порог M6 и M7: средний ≥ 3,5, ни одного ниже 3; раньше — справочно. Лимит: 2 цикла «правки → плейтест»; не взят порог — запасной (средний ≥ 3,0, ни одного ниже 2); не взят и он — `passes: false`, запись в итог и `QUESTIONS.md`.
